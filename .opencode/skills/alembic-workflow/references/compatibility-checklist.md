# Alembic Compatibility Checklist

This checklist ensures every migration works on both SQLite and PostgreSQL. Review every generated migration file against this list before committing.

## Quick Scan

Open the generated migration file and search for these patterns:

```
Ctrl+F:  now()        → must be sa.func.now()
Ctrl+F:  jsonb        → must be sa.JSON()
Ctrl+F:  ILIKE        → must use ilike() method
Ctrl+F:  text('1')    → must be text('true') for booleans
Ctrl+F:  text('0')    → must be text('false') for booleans
Ctrl+F:  SERIAL       → must be Integer + autoincrement=True
Ctrl+F:  psycopg      → must not appear
```

## Detailed Rules

### 1. Timestamps

**WRONG:**
```python
sa.Column('created_at', sa.DateTime(), server_default=sa.text('now()'))
sa.Column('created_at', sa.DateTime(), server_default=sa.text("datetime('now')"))
```

**CORRECT:**
```python
sa.Column('created_at', sa.DateTime(timezone=True), server_default=sa.func.now())
```

`sa.func.now()` compiles to `CURRENT_TIMESTAMP` in SQLite and `now()` in PostgreSQL.

### 2. Boolean Defaults

**WRONG:**
```python
sa.Column('activo', sa.Boolean(), server_default=sa.text('1'))
sa.Column('activo', sa.Boolean(), server_default=sa.text('0'))
```

**CORRECT:**
```python
sa.Column('activo', sa.Boolean(), server_default=sa.text('true'))
sa.Column('activo', sa.Boolean(), server_default=sa.text('false'))
```

`sa.text('true')` and `sa.text('false')` work in both SQLite and PostgreSQL.

### 3. JSON Columns

**WRONG:**
```python
sa.Column('data', postgresql.JSONB())
sa.Column('data', sa.JSONB())
```

**CORRECT:**
```python
sa.Column('data', sa.JSON())
```

SQLite doesn't have JSONB. Use `sa.JSON()` which works on both dialects.

### 4. Case-Insensitive Search

**WRONG:**
```python
stmt = select(User).where(User.name.ilike('%test%'))  # This is fine
op.execute("SELECT * FROM users WHERE name ILIKE '%test%'")  # WRONG in raw SQL
```

**CORRECT:**
```python
# In SQLAlchemy ORM (always correct)
stmt = select(User).where(User.name.ilike('%test%'))

# In migration raw SQL (avoid if possible)
op.execute("SELECT * FROM users WHERE LOWER(name) LIKE LOWER('%test%')")
```

ILIKE is PostgreSQL-specific. SQLAlchemy's `.ilike()` compiles correctly per dialect.

### 5. Enum Types

**WRONG:**
```python
sa.Column('status', sa.String(20))
sa.Column('tipo_iva', sa.Enum('GRAVADO', 'EXENTO'))  # Missing create_type
```

**CORRECT:**
```python
sa.Column('tipo_iva', sa.Enum('GRAVADO', 'EXENTO', name='tipo_iva', create_type=True))
```

`create_type=True` ensures the ENUM type is created in both SQLite (as a CHECK constraint) and PostgreSQL (as a CREATE TYPE).

### 6. Integer Primary Keys

**WRONG:**
```python
sa.Column('id', sa.Integer(), primary_key=True)  # No autoincrement
```

**CORRECT:**
```python
sa.Column('id', sa.Integer(), autoincrement=True, primary_key=True)
```

SQLite requires explicit `autoincrement=True` for auto-incrementing IDs.

### 7. Foreign Keys

**WRONG:**
```python
sa.ForeignKeyConstraint(['user_id'], ['users.id'])  # Missing ondelete
```

**CORRECT:**
```python
sa.ForeignKeyConstraint(['user_id'], ['users.id'], ondelete='RESTRICT')
sa.ForeignKeyConstraint(['user_id'], ['users.id'], ondelete='CASCADE')
sa.ForeignKeyConstraint(['user_id'], ['users.id'], ondelete='SET NULL')
```

Always specify `ondelete`. Use `RESTRICT` for data integrity, `CASCADE` for child records, `SET NULL` for optional references.

### 8. Naming Convention

The project uses `naming_convention` defined in `Base.metadata` (`database.py`). When creating constraints manually in migrations, follow these patterns:

```python
# Primary key
name='pk_tablename'

# Unique constraint
name='uq_tablename_columnname'

# Foreign key
name='fk_tablename_columnname_referredtable'

# Check constraint
name='ck_tablename_constraintname'

# Index (auto-generated by Alembic)
name='ix_tablename_columnname'
```

### 9. DECIMAL for Money

**WRONG:**
```python
sa.Column('precio', sa.Float())
sa.Column('precio', sa.Numeric(10, 2))  # Works but prefer DECIMAL
```

**CORRECT:**
```python
sa.Column('precio', sa.DECIMAL(10, 2))
```

Always use `DECIMAL` for monetary values. Never use `Float` for money.

### 10. Server Defaults for Strings

**WRONG:**
```python
sa.Column('estado', sa.String(20), server_default='PENDIENTE')  # Missing quotes
```

**CORRECT:**
```python
sa.Column('estado', sa.String(20), server_default='PENDIENTE')
```

String defaults work in both dialects. Just make sure the value is a string literal.

## Auto-Generate Specific Issues

When using `alembic revision --autogenerate`, Alembic inspects the current database and compares it to the models. Be aware of:

### PostgreSQL-specific types in autogenerate

If the current database is PostgreSQL, autogenerate may produce:
- `postgresql.JSONB()` → change to `sa.JSON()`
- `postgresql.ENUM(...)` → change to `sa.Enum(..., create_type=True)`
- `postgresql.ARRAY(...)` → avoid, use JSON or separate table

### SQLite-specific issues in autogenerate

If the current database is SQLite:
- `render_as_batch=True` handles ALTER TABLE limitations
- Enum types may not be detected correctly
- Some constraints may be missing from the diff

**Best practice:** Always generate migrations against PostgreSQL (the source of truth), then verify they work on SQLite via `render_as_batch=True`.

## Verification Commands

After reviewing the migration, test it:

```bash
# Test on SQLite
alembic upgrade head

# Test on PostgreSQL (Docker)
docker compose up -d db
DATABASE_URL=postgresql+psycopg://yanesu_user:pass@localhost:5432/yanesudb alembic upgrade head

# Verify schema
alembic current
alembic history
```
